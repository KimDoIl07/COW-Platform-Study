이 영상은 벡엔드가 왜 생겨났는지로부터 시작합니다.
초기 인터넷은 단순한 문서를 그대로 보여주는 수준에 그쳤으나, 방문자가 글을 남기는 '방명록'이나 '검색창'처럼 사용자마다 실시간으로 다른 결과를 보여줘야 하는 기능이 필요해졌습니다.
그래서 서버 사이드 렌더링(SSR)을 통해 미리 만들어진 파일을 주는 것이 아니라, 요청이 들어올 때마다 서버가 그 자리에서 바로 계산을 하고 화면을 새로 조립해주는 방식이 탄생하게 되었고, 이를 가능하게 해준 첫 기술이 바로 CGI고 이후, PHP,JSP 등으로 발전했습니다.
또한, PHP, 파이썬, 자바, Node.js, 고(GO) 등 어떤 벡엔드 언어든 변수, 조건문, 반복문, 함수, 데이터 타입이라는 다섯 가지 공통 뼈대 위에서 작동합니다. 여기에 클래스, 예외 처리, 모듈 등이 더해집니다. 언어 간의 차이는 약간의 문법 차이 정도일 뿐 구조는 동일합니다.
언어별 특징으로는 PHP의 웹이 동적으로 변하던 시절 폭발적으로 퍼졌으며, 라라벨 프레임워크와 함께 사용됩니다.
파이썬의 경우 장고(Django)와 API 서버에 특화된 패스트 API가 주로 쓰입니다.
자바 & 스프링의 경우 대기업, 금융권, 공공기관의 표준으로 수십년간 검증된 안정성을 가집니다.
고(GO) 는 구글이 만든 언어로 빠르고, 동시에 수천 개의 요청을 처리하는 대규모 트래픽 인프라에 특화되어있습니다.
다음으로, 데이터베이스의 등장과 MVC 패턴에 대해 이야기합니다. 데이터베이스의 경우 서버가 꺼져도 방명록 글 등의 데이터를 영구적으로 보관하고 빠르게 찾기 위해 관계형 데이터베이스(MySQL 등)가 도입되었습니다.
MVC 패턴은 시간이 지나면서 코드가 복잡해지면서 역할을 나누기 위해 도입된 모델(M), 화면을 그리는 뷰(V), 교통정리를 하는 컨트롤러(C)로 분리했습니다. 이 과정에서 재고 확인, 결제 등의 핵심 규칙인 '비즈니스 로직' 개념도 함께 자리잡았습니다.
이후 모바일이 나타나면서 또다시 변화하기 시작하였고 보안을 위해 기술이 생기고 발전하였습니다.
아이폰 등 모바일 앱이 등장하면서 서버가 HTML 대신 데이터 자체를 공급해 줄 필요가 생겼고, 키-값 형태로 데이터를 주고받는 'API'와 'JSON' 형식이 핵심이 되었습니다. 이로 인해 벡엔드는 데이터 공급자, 프론트엔드는 화면 제작자로 역할이 확실히 나뉘었습니다.
보안의 경우에도 HTTP의 무상태성을 해결하기위해 세션과 쿠키, JMT(JSON Web Token) 과 같은 토큰 기술이 생겼습니다. 또한, 사용자가 누구인지 확인하는 인증과 권한을 확인하는 인가가 필수가 되었고, 비밀번호는 해싱 과정을 거쳐 안전하게 보호해줍니다.
